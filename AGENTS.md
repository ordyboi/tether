# Tether

A private, encrypted location sharing app for friends and family.
DO NOT EDIT THIS FILE DIRECTLY.

Github Issues is the platform we use to create tickets of work. You can access this using the `gh` cli.

Never search outside this folder or try to control a connected mobile device, instruct the user to do it.

## Invariants

- room precision policy is set at creation and never changes; no settings screen exposes it.
- `fix` has exactly one server timestamp, rounded to the minute — no global timestamp helper, no Postgres trigger.
- all `fix` ciphertexts are padded to the same length before upload.
- nothing writes an IP address or user agent — not the app, not the reverse proxy, not the host.
- one wrapper function talks to FCM; data-only payloads, never a `notification` block.
- envelopes are only issued for epochs at or after a member's `joinedEpoch`.
- the invite link fragment after `#` never appears in a request, a log, or a server test fixture.
- `fix`, `precision_request`, and `precision_grant` reference aliases, never user IDs

## Code rules

- before doing anything create a new branch or check you're on one
- follow TDD, test your changes before implementation
- never run a dev server to verify changes, you can run builds of the app to test but a device must be connected
- always run a format, lint and test before commiting work
- use conventional commits when commiting work
- never leave verbose comments, let the code explain itself, if you have to comment make it a concise one liner
- for any typescript code avoid `undefined` as much as possible, `any` types, `as` casting and return types
- when working with environment variables define them at the monorepo root and let each workspace import them by `zod` validation utility

## Database rules

Always work with `db:push` in a local docker compose for `postgres`, never create migrations or migrate the database, they are for prod and staging only.

## PR rules

When asked to submit a PR, keep the PR title as `Issue #X: {}` in the `{}` placeholder replace with a concise explanation of what you implemented in plain-english not what you done, keep that as a short description
